# 第一阶段 · 联系我们

官网使用 GitHub Pages 提供联系页，由现有 Sites API 保存留言。姓名、邮箱、公司、电话、微信和留言只写入私有 D1 表 `contact_messages`。编号用于对账，公开接口不提供留言查询。本站每次在保存成功后显示编号，并单独显示邮件通知状态。无法确认保存时保留访客输入；同一标签页中的原样重试复用原编号。

## 值班和回复

负责人邮箱为 `info@amachina.com`。目前尚未启用企业发信服务。负责人可在已授权的后台打开「悦悦 · 官网对话服务」的数据库，查看 `DB → contact_messages`，读取 `payload.email` 和留言，从业务邮箱直接回复。访客也可以在保存回执中点击「用自己的邮箱发送这条留言」，确认发送含编号的邮件。

服务端已实现 Resend 通知。启用时，在 Sites 环境变量中配置 `RESEND_API_KEY` 和 `CONTACT_FROM`（发件域名须在 Resend 验证），重新部署后台，再将 GitHub Actions 仓库变量 `CONTACT_MAIL_ENABLED` 设为 `true`。后台与 GitHub Actions 已配置同名加密密钥 `CONTACT_RETRY_TOKEN`。可以手动运行工作流「Retry contact notifications」处理积压。已保存的待发留言会使用原编号投递到负责人邮箱，邮件的 Reply-To 为访客填写的邮箱。

数据库中 `pending` 表示待发送，`sent` 表示邮件服务已受理，`provider_id` 可供查验。工作流每十五分钟检查到期记录，每轮处理最多十条。首次尝试后超过 23 小时仍无服务商回执的记录标为 `review`，负责人需按编号查询服务商记录，再决定是否人工回复。启用后，请用受控访客邮箱提交一条留言，在负责人收件箱核对编号，点击回复，再从访客邮箱确认回信。

## 验收记录

| 场景 | 证据 |
| --- | --- |
| 生产保存 | Sites API 第 3 版已发布。测试编号 `13aa4666-bca0-4402-9414-21021dfbf86e` 返回已保存、通知待发送。 |
| 数据库故障及输入错误 | 自动化测试验证保存失败返回 503，错误输入不会写库。 |
| 失败重发与直接回复 | 在测试发信接口模拟首次失败、重试成功，确认两次投递使用同一幂等键，收件人为指定邮箱，Reply-To 为访客邮箱。 |
| 收件人与访客的真实邮件往返 | 待配置企业发信服务并完成双端邮箱验收。 |

在仓库根目录执行 `npm ci`、`npm run build`、`npm run check` 和 `npm run test:sites`。上线后可安装 Chromium（`npx playwright install chromium`），再运行 `CONTACT_ACCEPTANCE_LIVE=1 node scripts/check-contact-browser.mjs`。此命令会在生产库写入两条标记为验收的留言，覆盖桌面双击、移动端丢失回执重试及重复请求。应从私有数据库按返回编号核对每笔只有一条。

更新后台代码时，在本站仓库根目录运行 `node scripts/prepare-api.mjs <现有 Sites API 检出目录>`。在对应 Sites 项目执行 `bash scripts/build.sh` 和 `node scripts/validate-artifact.mjs`，通过 Sites 发布源码及对应构建。GitHub Pages 发布负责前端。
